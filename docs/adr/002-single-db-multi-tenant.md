# ADR-002: 单库 + tenant_id 多租户隔离

- **Status**: Accepted
- **Date**: 2026-07-24

## Context

XCMS 服务于集团多个租户（子公司、产线、项目等），需要数据隔离。不同租户规模差异大，部分租户未来可能需要独立数据库。

## Decision

采用 **单库 + tenant_id 列** 进行多租户数据隔离，通过 `AbstractRoutingDataSource` 预留多库扩展能力。

所有业务表的每行数据携带 `tenant_id`，查询自动过滤，写入自动填充。

## Alternatives

### 方案 B：每租户独立 Schema

- **优点**：物理隔离更好
- **缺点**：管理复杂、跨租户查询困难、不适合大量小租户

### 方案 C：每租户独立数据库

- **优点**：完全物理隔离
- **缺点**：成本高、跨租户极难、不适合起步阶段

## Consequences

### 正面

- 起步成本最低，一个数据库实例
- 跨租户查询简单（同一库内）
- 运维简单

### 负面

- 逻辑隔离而非物理隔离（需确保拦截器可靠）
- 大租户可能影响其他租户
- 单租户独立备份困难

### 缓解措施

- JPA `@TenantId` 自动隔离 + 拦截器兜底
- `AbstractRoutingDataSource` 预留，未来大租户可切独立库
- 设计阶段确保所有数据可按 tenant_id 提取迁移

### 演进路径

```
阶段1（当前）：单库 + tenant_id
阶段2（按需）：单库 + 大租户独立库（路由切换）
阶段3（成熟）：共享库 + 独立库 + 独立部署
```
