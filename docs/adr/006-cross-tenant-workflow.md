# ADR-006: 跨租户流程——归属权与参与权分离

- **Status**: Accepted
- **Date**: 2026-07-24

## Context

XCMS 需要跨租户流程（如子公司A发起→集团审批→子公司B执行）。在共享引擎中，如何实现跨租户流程流转和数据访问控制是核心难题。

## Decision

采用 **归属权与参与权分离** 原则：

- **流程实例归属一个租户**（发起方租户），数据属于该租户，不转移
- **任务可跨租户分配**，任何租户的用户都可被分配任务
- **任务查询是用户维度的**（跨租户查"我的待办"）
- **数据访问按节点配置过滤**（跨租户参与者只能看到授权字段）

三层控制：
1. 流程定义时：每个节点配置参与租户 + 数据权限
2. 流程运行时：根据配置分配任务并生成跨租户授权令牌
3. 任务处理时：校验参与权 → 按配置过滤数据 → 审计

## Alternatives

### 方案 B：流程实例跨租户迁移

流程到达某租户节点时，将流程实例迁移到该租户。

- **优点**：数据归属随流程移动
- **缺点**：迁移复杂、数据一致性风险、审计困难

### 方案 C：每租户独立流程 + API联动

- **优点**：隔离好
- **缺点**：不是真正的跨租户流程，体验差

## Consequences

### 正面

- 流程数据不迁移，简单可靠
- 跨租户参与通过任务分配实现，自然
- 数据访问严格按节点配置控制，安全
- 全程审计

### 负面

- 跨租户任务的数据访问需要额外过滤逻辑
- 节点配置较复杂

### 独立部署场景

独立部署的租户与共享引擎不互通流程。预留 `BridgeNode`（桥接节点）接口，未来通过API联动两个独立流程。
