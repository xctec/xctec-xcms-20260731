# ADR-003: 分层管理面架构

- **Status**: Accepted
- **Date**: 2026-07-24

## Context

XCMS 需要管理级联租户（集团→子公司→产线，最多10级）。管理面需要决定：
- 父租户能否管理子租户？
- 父租户能否看到子租户的业务数据？
- 是否需要独立的租户管理系统？
- 是否需要"上帝视角"？

## Decision

采用 **分层管理面（方案C）**：管理面本身分层级，与租户树对应。每一级租户都有自己的管理后台，管自己的子树。

核心原则：
- **管理可见**为默认：上级可查看下级的元数据、配置、用量
- **业务可见**需授权：上级默认不可见下级业务数据，需通过"业务可见授权"流程临时获取
- **管理面与业务面逻辑分离**：管理API（/admin/**）与业务API（/api/**）分离

## Alternatives

### 方案 A：统一平台（管理业务不分）

- **优点**：简单
- **缺点**：管理权限和业务权限耦合，安全边界模糊。不适合集团级。

### 方案 B：独立管理面（不分层）

一个运营管理平台管理所有租户，不分层级。

- **优点**：管理集中
- **缺点**：子公司管理员能看到其他子公司数据，权责不对齐

## Consequences

### 正面

- 匹配集团现实层级管理结构
- 每级管理员只管自己的子树，权责对齐
- 管理面与业务面分离，安全边界清晰
- 独立部署友好（带走自己的管理面+业务面）

### 负面

- 管理面逻辑较复杂
- 上下级管理面需要同步数据

### 关键设计

在单体中，管理面与业务面是逻辑分离（不同API路径 + 权限控制），不是物理分离。
